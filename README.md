# tiralechat.hu

The source of the portfolio site of Tira Le Chat, a tattoo artist in Budapest.

**Live:** [tiralechat.hu](https://tiralechat.hu/) · **English:** [tiralechat.hu/en/](https://tiralechat.hu/en/)

One page, one pinned stage, seven acts played on scroll: Tira's portraits
stick onto the wall pose by pose, a folder of polaroids streams the finished
tattoos past, the designs land on a bare back where a tattoo machine inks one
of them in, the drawings and paintings drift by, a hand pulls the folder away
for the news, and the closing act asks when you're coming. Behind it a sky
that keeps billowing, in front of it an ink trail that follows the mouse. Two
languages, built from one source.

## Built with

- **No framework.** Hand-written ES modules, one concern per file — about
  4,600 lines of JavaScript across 28 of them, and one 4,100-line stylesheet.
- **[Vite](https://vite.dev/) 8** for the dev server and the build.
- **[GSAP](https://gsap.com/) 3** — ScrollTrigger, ScrollSmoother and
  SplitText. The only runtime dependency.
- **One timeline for the whole page.** Every act adds its part to a single
  paused master timeline that a pinned ScrollTrigger scrubs, so an act can be
  added or lengthened without retuning any scroll distances. On resize the
  scene is rebuilt and the reader is put back in the same act.
- **WebGL, by hand.** The billowing sky and the metaball ink trail are small
  shaders written against the raw WebGL API — no 3D library.
- **CSS as written**, no preprocessor and no utility framework. Three
  compositions by aspect ratio — wide, compact and portrait — each tuned on
  its own rather than squeezed from one.
- **Pictures load in the order the page shows them.** The first screen comes
  first; the later acts are built on blank placeholders of the right shape
  and get their pictures in turn, so the page scrolls as soon as the hero
  stands. Every `<img>` carries a generated `srcset`/`sizes` measured per
  view.
- Self-hosted fonts, WebP imagery, and the HTML comments stripped from the
  build by a small Vite plugin.

## Laid out like this

```
index.html            the Hungarian page — the only one edited by hand
en/index.html         the English page — GENERATED, never edit
src/
  main.js             starts everything, in order
  stage.js            the pinned stage and its master timeline
  hero-*.js           the opening: intro, the pile of poses, its scroll part
  works.js            one module per act: works, designs, backpiece,
  designs.js …        paintings, news, contact
  late-images.js      the order the pictures load in
  sky.js, ink-trail.js  the two WebGL layers
  lightbox.js, news-gallery.js, mobile-menu.js, preloader.js, …
  style.css           the whole look, wide first, then the compact and
                      portrait overrides at the end
  i18n.js             the few strings the scripts write, at run time
tools/i18n/           the English page's generator and its language file
tools/images/         the responsive image copies and srcset generator
video/                a short social reel rendered from the site's own parts
public/               fonts, images, sitemap, robots
```

Most of the explanation lives in the code: the files carry long comments
about why a thing is shaped the way it is, which is usually more interesting
than what it does.

## Running it

Needs Node 20.19+ or 22.12+ (what Vite 8 asks for).

```bash
npm install
npm run dev
```

| Command | What it does |
| --- | --- |
| `npm run dev` | generates the English page, then serves the site at `localhost:5173` |
| `npm run build` | the same, then writes the deployable site to `dist/` |
| `npm run preview` | serves `dist/` as it will be served live |
| `npm run en` | regenerates the English page on its own |

`dist/` is the whole site: static files, uploaded as they are.

## The two languages

Hungarian is the source. `index.html` is the only page edited by hand;
`en/index.html` and `src/i18n-en.js` are generated from it by
`tools/i18n/build-en.mjs`, which puts in the translations from
`tools/i18n/en.json`. It runs by itself before `dev` and `build`.

So an English text is changed in `en.json`, never in `en/index.html`. A
Hungarian text changed in `index.html` needs its row in `en.json` updated
too — the generator prints every row whose Hungarian it can no longer find.
`tools/i18n/README.md` has the details.

## Pictures

The smaller copies under `public/img/r/` and the `width`/`height`/`srcset`/
`sizes` of every `<img>` are generated by the scripts in `tools/images/`;
its `README.md` says how to add a new picture.
